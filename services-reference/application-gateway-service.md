# application-gateway-service

**Layer:** 4 (Application Gateway) · **Port:** 8006 · **Status:** **Real — R3.5-complete, §22-signed-off** (Reza ran `smoke.sh` over the full stack). Built as a **streaming reverse-proxy edge**: route table → proxy to seven lower services (the five substrate/capability services plus harness-runtime and execution-engine), edge JWT termination + identity forwarding with ADR-018 `X-Internal-Key` attestation, CORS, and health aggregation. **R6 hardening is underway:** the **versioned public OpenAPI contract** (Slice 1), the **edge rate-limit + request-size guard** (Slice 2), the gateway's **own org-scoped Postgres + the integration-key store/validator** (Slice 3, ADR-019 — its first database), the **published-agent surface + integration-key CRUD** (Slice 4 — publish/mint/invoke, binding-enforced), and **per-key / per-origin CORS** for the agent widget plane (Slice 5), **member console chat** (Slice 6 — persisted, private-to-creator, riding the harness), and **webhook ingress** (Slice 7 — the first public, signature-gated door, firing the engine) are built; MCP and sole-ingress remain.

## What it is now (real today)

R3.5 service #6 built the gateway as a thin, stateless edge:

* **Reverse proxy** — a longest-prefix route table maps public paths to upstreams and streams requests/responses through (`httpx` send `stream=True` → `StreamingResponse` + `BackgroundTask` to close the upstream). Seven lower services sit behind it: auth (`/v1/auth`, `/v1/orgs`, `/v1/invitations`, `/oauth`), credential-broker (`/credentials`), knowledge-graph (`/api/v1/graphs`, `/api/v1/recipes`), knowledge-retriever (`/v1/search`, `/v1/graph`), capability-registry (`/api/v1/{capabilities,tools,instances,executions}`) on Layers 1–2, plus harness-runtime (`/v1/harnesses`) and execution-engine (`/v1/engine`) on Layer 3. Health aggregation (`/health/upstreams`) rolls up only the five substrate/capability services.
* **Edge JWT termination** — `GATEWAY_AUTH_MODE` (`dev` | `jwt`) verifies the caller's token at the edge, then forwards identity as `X-Principal-*` / `X-Organisation-Id` headers. Inbound copies of those trusted headers are **stripped first** (anti-spoof), so upstreams trust only what the gateway asserts. Only `/v1/auth` and `/oauth` bypass edge auth; `/v1/orgs` and `/v1/invitations` are proxied to auth-service but stay authenticated.
* **Edge-auth attestation (ADR-018)** — every forwarded request carries a shared `X-Internal-Key` (`INTERNAL_SERVICE_KEY`; any client-supplied copy stripped first) so upstreams in gateway-mode can prove the request actually transited the gateway and trust the `X-Principal-*` headers.
* **CORS** — `CORSMiddleware`, origins from config.
* **Health aggregation** — `GET /health` (self) and `GET /health/upstreams` (rolls up the five substrate/capability upstreams' health with a bounded timeout).
* **Canonical ORA-37 error envelope** — every 4xx/5xx the gateway returns (its own errors AND normalized upstream errors) is the canonical `{error:{code, message, requestId, retryable, details?}}` shape via the shared `oraclous_errors` emitter; upstream error bodies are drained and discarded so no upstream stack trace / SQL / internal host leaks through the edge (Interface Contracts §3 rule 8). `requestId` is the server-minted `req_*` correlation id set by `RequestIdMiddleware` and echoed in `X-Request-Id`.

It is the strictest case of the §21 no-logic-in-handlers rule: the gateway proxies and applies policy, it never executes business logic or touches substrate.

## R6 hardening — shipped so far

* **Versioned public OpenAPI contract (Slice 1, ADR-015)** — the gateway publishes the canonical `openapi/v1.yaml` at `/v1/openapi.json` + `/v1/openapi.yaml` + a Swagger UI at `/docs` (served before the proxy catch-all; FastAPI's leaky auto-spec is disabled). The spec carries the closed ORA-37 `ErrorEnvelope` (byte-identical to the cross-repo schema), per-operation `x-stability`, and only operations that actually route (no `/internal` plane). An `openapi-diff-gate` CI job blocks any breaking change to a `stable` operation. `openapi/v1.yaml` is now the source of truth for what the gateway exposes.
* **Edge rate-limit + request-size guard (Slice 2)** — two pure-ASGI edge middlewares (never `BaseHTTPMiddleware`, so the streaming proxy is never buffered):
  * **Request-size guard — FAIL-CLOSED:** `413 PAYLOAD_TOO_LARGE` when a body is not positively within `MAX_REQUEST_BODY_BYTES` — a Content-Length fast-path plus an authoritative byte counter that stops reading at `max+1` (catches chunked / omitted-length; never buffers an oversize upload to measure it).
  * **Rate limit — FAIL-OPEN:** a Redis-backed (own DB 2) per-client-IP fixed window (`INCR`+`EXPIRE` in a transactional pipeline) → `429 RATE_LIMITED` + `Retry-After`. A Redis outage logs + **allows** — the gateway is the sole ingress, so throttling on a Redis blip would self-DoS the platform; short Redis socket timeouts make the fail-open instant under a partition. Liveness + contract probes (`/health*`, `/v1/openapi.*`, `/docs`) are exempt.
  * **X-Forwarded-For trust boundary** (`TRUSTED_PROXY_COUNT`, default 0): at 0 the client-IP key is the socket peer and XFF is ignored (a rotating XFF can't fork buckets); at N>0 the (N+1)-th hop from the right, never the spoofable left-most. **Security ruling (recorded):** fail-open rate limit, fail-closed size guard, count-XFF-from-the-right — residual risks: no volumetric protection during a Redis outage (alert-driven), shared egress (NAT) shares a bucket, a misconfigured `TRUSTED_PROXY_COUNT` re-opens spoofing (default 0 is the safe floor). Both 429/413 are the ORA-37 envelope, carry `X-Request-Id`, and (CORS sits outside the guards) carry `Access-Control-Allow-Origin` so a browser can read them.
* **Gateway datastore + integration-key store/validator (Slice 3, ADR-019)** — the gateway gains its **first database**: a dedicated, **`organisation_id`-scoped Postgres** (app-layer tenancy like the rest of the platform — no RLS today, RLS-ready; its own `alembic_version_application_gateway` lineage, applied by a `gateway-migrate` one-shot). It holds the **`integration_keys`** store: one row per key with a UNIQUE non-secret `key_prefix` (lookup), a SHA-256 `key_hash` (the plaintext is never stored), `last4`, an exactly-one binding (a published-agent slug XOR a capability allow-list, CHECK-enforced), per-key CORS/rate-limit, `status`, and an optional TTL. An **inbound integration-key validator** resolves an `oak-`/`oag-` bearer WITHOUT a JWT: prefix lookup → **constant-time** hash compare (even on a miss) → status/TTL checks → mint a **`SERVICE_ACCOUNT`** Principal under the key's org. **Fail-closed** on every bad key (401, before any upstream call); a belt-and-braces guard refuses any principal with no org; a DB outage degrades the key path to 503 (never a 500), `/health` stays up. The JWT/dev edge auth is unchanged — the key branch is purely additive. *(The per-key binding is **stored** here and **enforced** in Slice 4, which also adds the public key CRUD + mint.)*
* **Published-agent surface + integration-key CRUD (Slice 4)** — the management + public planes that make the S3 key store usable; nine gateway-local routes (served before the proxy). A second table, `published_agents` (org-unique `(org, slug)`), binds a public slug to a capability/harness descriptor.
  * **Management — member JWT, org-scoped** (`require_member` rejects a key bearer with 403; org-admin role gating is deferred to a platform-wide roles pass, matching the no-roles-yet posture): `POST /v1/agents` publishes; `GET /v1/agents` lists; `POST /v1/integration-keys` mints (the plaintext is returned **once**, bound to a slug XOR a capability allow-list); `GET` lists **redacted** (never the hash/secret); `GET /{id}`; `POST /{id}/rotate` swaps the secret in place (the old key dies); `DELETE /{id}` revokes (a **terminal** tombstone — a rotate never resurrects a revoked key).
  * **Public — integration-key, binding-enforced** (`require_bound_key` fail-closed 403s unless the key's `bound_agent_slug` equals the path slug — a member JWT, a capability-only key, and a wrong-slug key are all rejected **before any forward**): `GET /v1/agents/{slug}` returns a narrow public projection (slug + display + description, no internal ids); `POST /v1/agents/{slug}/invoke` runs the bound capability on the harness (`/v1/harnesses/execute` with `manifest_ref` + the ADR-018 trusted headers, the org from the verified key). The result is projected to a **narrow** `InvokeResponse` — status collapsed to a coarse `succeeded`/`pending`/`failed` + a generic error; the raw harness `error_message` (un-redacted exception text) **never** reaches the public plane; a malformed upstream body is a 502, not a 500.
* **Per-key / per-origin CORS (Slice 5)** — an embeddable published-agent widget is allowed only on the origins its integration key lists. Each key carries a `cors_origins` allow-list (the dormant S3 column, now live); it rides the resolved key on `request.state`. A path-scoped pure-ASGI **`AgentCorsMiddleware`**, added OUTSIDE the gateway-wide CORS so it wraps it, governs CORS for the two browser routes (`GET /v1/agents/{slug}` + `.../invoke`) **only** — a no-op everywhere else (the gateway-wide CORS stays authoritative for the proxied + management routes). Because a browser **preflight** carries no `Authorization` (and per-org slugs can't resolve an org without the key), the preflight is answered **permissively** (reflect the origin, **never** credentials — the key gates execution, the actual response's per-key ACAO gates the read); on the keyed response the middleware strips the inner CORS's `Access-Control-Allow-Origin`/credentials/`Vary`/expose and re-adds a single ACAO **iff** the request Origin is in the key's `cors_origins` (exact match; **fail-closed** — a key with no `cors_origins` allows no origin). No credentials are ever set on this plane (the key is an explicit header, not a cookie), so it avoids the wildcard-with-credentials trap. Origins are validated `scheme://host[:port]` at mint. **Security ruling (recorded):** the per-key plane is credential-free + exact-match + fail-closed. *Separate pre-existing finding (NOT from S5, recorded for triage):* the **gateway-wide** CORS ships `allow_origins=["*"]` + `allow_credentials=True`, which Starlette turns into origin-reflection-with-credentials on the proxied/management plane — it should be tightened. **Resolved (#206, tech-lead call):** the gateway-wide CORS now sets `allow_credentials=False` — the FE authenticates with `Authorization: Bearer` (not cookies), so a permissive origin list is safe (Starlette emits a literal `ACAO: *`, the Bearer token is the gate); production should still pin `GATEWAY_CORS_ORIGINS` for defense-in-depth.
* **Member console chat (Slice 6)** — a persisted, multi-turn member chat with a published agent. Two more gateway-owned tables (migration `0003`): `chat_threads` (org-scoped AND **private to its creating member** — every read/write filters `organisation_id` + `created_by_user_id`, so a cross-member/cross-org access is **404**) + `chat_messages` (role-checked, FK-CASCADE, an `execution_id`/`total_tokens` audit). A thread binds to a published-agent **slug** (reusing the S4 resolution). **Member-only** (`/v1/chat/...`, a USER JWT — a key bearer is 403): start a thread, send a message, list one's own threads, read a transcript, soft-delete. A **turn** (`chat_turn_service`): resolve the thread + bound agent → fold the **capped** prior history (turn + char budget, oldest dropped, `system` excluded) + the new message into the **single** harness `input` (the harness is stateless one-OHM-one-input) → persist the user turn **before** the call (so it survives a failure) → run `/v1/harnesses/execute` (ADR-018 headers, org from the principal) → on `SUCCEEDED` persist the assistant reply; `ESCALATED` → a `pending` turn (no stored answer); `FAILED` → a **generic** assistant turn (the raw harness `error_message` **never** reaches the client, the S4/S5 lesson); non-2xx → 502. *Recorded follow-up (LOW, out of S6 scope):* the history-fold transcript is a **bounded** prompt-injection vector (a member's own private thread, no cross-tenant/secret impact) — fence/escape content or pass a structured conversation field once the harness gains one.
* **Webhook ingress (Slice 7)** — the platform's **first public, Bearer-less external door** (three PRs across three services: a credential-broker webhook-secret namespace #209, an execution-engine `POST /v1/engine/events` event-fire #210, the gateway ingress #211). A gateway-owned `webhook_subscriptions` table (migration `0004`) maps an **opaque, unguessable** id → {org, target published-agent slug, pinned `signature_scheme` (generic HMAC-SHA256, v1), `broker_secret_ref`, `enabled`}. The signing **secret never lives in the gateway** — it is minted in and resolved from the **credential-broker** (AES-256-GCM behind X-Internal-Key, ADR-008), because verifying an inbound HMAC needs the plaintext recomputed and the stateless edge must not hold recoverable material; the gateway stores only the reference. **Inbound** `POST /v1/webhooks/{id}` (public — added to `_PUBLIC_PREFIXES`, authenticated by **signature** not a bearer): resolve the sub → resolve the secret from the broker → verify HMAC-SHA256 over the **exact raw body** (`X-Hub-Signature-256: sha256=<hex>`, `hmac.compare_digest`; the SizeGuard buffers + replays the bytes so the signature stays byte-exact; the scheme is **pinned**, never header-inferred → no downgrade) → resolve the bound published agent → mint a **SERVICE_ACCOUNT** principal from the **sub's org** → forward `POST /v1/engine/events` with the ADR-018 trusted headers (idempotency = `X-Webhook-Delivery` else `sha256(body)`; the engine reuses the R5 durable spine, deduped on `(org, idempotency_key)`). The **whole auth-failure family** (unknown/disabled sub, unresolvable secret, bad/absent signature, unpublished target) returns a **uniform 404** — anti-enumeration; engine non-2xx/unreachable → 502; the external caller asserts nothing (its `X-Principal-*`/`X-Internal-Key` are stripped). **Member-only** CRUD `/v1/webhook-subscriptions` (a USER JWT — a key bearer is 403; **not** matched by the `/v1/webhooks` public prefix, so it stays edge-authed): create (mint a `whsec_` secret → store in the broker → return the plaintext + the `webhook_path` **once**), list + delete (org-scoped). **Security ruling (recorded):** constant-time HMAC over raw bytes, secret-source = the broker, 404-never-403, org attested from the row. *Recorded follow-ups (LOW):* (a) per-source/per-subscription rate-limit is the T5 gate — deferred (the per-IP edge limit is the floor; the webhook door is the highest-risk public surface); (b) an orphan broker secret can dangle if a subscription row insert fails after the mint (harmless — never resolvable — but wants a broker delete endpoint + GC); (c) per-provider signature schemes (GitHub/Stripe/Slack) build on the same pure seam.

## R6 hardening targets (NOT built yet)

The following are the gateway's eventual contract surface and are **deferred to R6** (the "gateway-from-R5 vertical slices" plan is discarded; R6 owns these):

* Public REST APIs for harnesses/chats/capabilities/members; chat persistence (Slice 6)
* **MCP server** (expose workspace capabilities to external MCP clients) and **MCP client** (import external MCP tools into [capability-registry-service](capability-registry-service.md)) — Slice 8
* ~~Webhook receivers (+ signature verification)~~ — **shipped (Slice 7)**; embeddable widget endpoints remain
* **Per-key / per-origin CORS scoping** (Slice 5 — the edge-wide rate-limit + size guard shipped in Slice 2; per-*key* limits/CORS ride the integration-key store)
* **Sole-ingress** posture (closing upstream host ports) — a security-architect call; upstream ports stay open today for per-service smokes + defense-in-depth.

## Dependencies

* **Upstream:** [auth-service](auth-service.md) (human + machine authentication), [capability-registry-service](capability-registry-service.md), [knowledge-graph-service](knowledge-graph-service.md), [knowledge-retriever-service](knowledge-retriever-service.md), [credential-broker-service](credential-broker-service.md), [harness-runtime-service](harness-runtime-service.md) (`/v1/harnesses`), [execution-engine-service](execution-engine-service.md) (`/v1/engine`) — all proxied; the gateway never reads their secrets or substrate directly
* **Downstream consumers:** all external callers (the frontend; later, customers, MCP clients, webhook senders)

## What does NOT live here

* **Capability execution** — [capability-registry-service](capability-registry-service.md); the gateway proxies, it does not execute
* **Substrate writes** — the gateway never writes Neo4j or the credential store directly; it goes through the owning service
* **Business logic** — the gateway is a thin shell; logic lives in the lower layers
* **A database** — by design, the gateway is stateless **today**. (Forward note: **R6 adds a dedicated gateway-owned, org-scoped Postgres** for the integration-key store, published-agent records, and chat persistence — per [ADR-019](../adr/adr-019-r6-gateway-datastore-and-integration-key-authz-floor.md). This reverses the no-DB invariant for those three surfaces only; the proxy/auth/health paths stay stateless.)

## Architecture conformance (ORAA-4 §21)

Layered shape: package root `services/application-gateway-service/src/oraclous_application_gateway_service/` with `routes/` (`health_routes`, `proxy_routes` — the catch-all uses `response_model=None`), proxy/policy logic in `services/` (`proxy_service`, `health_service`), the route table + auth policy in `domain/`, the upstream client in `repositories/`, Pydantic-only `schema/`, `core/{config,dependencies,lifespan,auth}.py`. No business logic in handlers; no DB drivers anywhere (no DB). `structure_enforced: true`, `claimed_done: true`.

## Definition of Done (ORAA-4 §22) — MET

All 8 gates passed for the reverse-proxy edge: structurally conformant; not hollow (`check_no_stubs` zero findings, `claimed_done: true`); runs (`docker compose up` healthy, `GET /health` 200); real endpoints (integration: a request proxied to a real upstream via an in-process ASGI upstream; 502/504 on connect/timeout); end-to-end smoke (`tests/smoke/smoke.sh` over the full stack, `r3_5_gate` job); Reza personally signed off. The R6 hardening targets above are tracked separately and are **not** part of this DoD.
