# R3.5 Release-Seam Retrospective (ORAA-4 §14)

**Release:** R3.5 — make every backend service real, end-to-end, one service at a time (ORAA-4 §21/§22/§23).
**Board goal:** `ca8e1400-958f-455c-9fdd-3660272e3c8f` → **achieved** (locked by the closure PR #168 / `[ORAA-282]`).
**Spec pin:** legacy `develop@84152635`.

R3.5 existed because R2/R3 shipped **hollow**: stub endpoints, `NotImplementedError`, and real logic stranded in `oraclous-core-service`. The release rebuilt all six backend services for real under the hardened per-service Definition of Done (§22, 8 gates: structure §21 · not-hollow · runs · real endpoints · smoke-vs-real-substrate · Reza sign-off), graph-first, one service at a time.

**Outcome — all six services are REAL and §22-signed-off; the goal is closed honestly.** A fresh adversarial hollowness audit (two independent passes over the six services + a KB scan) found **zero** stub / empty / `NotImplementedError` / `501` / placeholder spots; every service runs a real `routes → services → repositories → substrate` chain. `check_no_stubs --all services` is clean and `claimed_done=true` is locked on all six (PR #168).

## 3. Mechanism gaps found and fixed (ORAA-4 §20 — fix the mechanism, not the rule-text)

| Gap | Discovery | Fix |
|-----|-----------|-----|
| plaintext credential at rest | broker shell wrote `json.dumps(credential)`; the smoke caught plaintext in the DB | AES-256-GCM (`core/security.py`); repo encrypts on write, service decrypts on read; **smoke now asserts ciphertext in the DB** |
| `httpx` missing from a service's runtime image | the **docker** smoke failed at import while the unit smoke passed (#158) | added the dep; lesson — docker smoke catches packaging gaps unit smoke cannot → docker smoke required for multi-service features (§9.3) |
| `claimed_done` flags lagged reality | #5 shipped but the flag wasn't flipped until a follow-up (#161); #1–#4 stayed false even though their projects were completed | flip status flags **in the feature/closing PR**; the R3.5 closure (#168) reconciled all six |
| smoke had no real-substrate variant | §22 demands smoke-vs-real | two-signature pattern: `smoke.sh` (key-free, CI) + a real-substrate script (operator/secret-gated) — carried forward |
| cross-org isolation by discipline only | needed proof of ADR-006 org-scoping | every service smoke asserts a cross-org denial (org B reading org A → 404) |
| gateway error envelope non-conformant | the gateway's own-error body shipped as `{error_code, message, request_id}` (flat) — it does **not** match the pinned ORA-37 contract `{error: {code, message, requestId, retryable, details?}}` | corrected by the FE-readiness error-contract slice (see §6); the contract already exists at `packages/errors/contract/` with a checksum-integrity gate |

**Non-gaps (correctly judged cosmetic):** the S2 "closed, not merged" GitHub-UI artifact — `git log` shows the squash on `main`; a concurrent base edit during merge produced a harmless UI inconsistency (trust `git log` over the UI). Nonce handling (`os.urandom(12)` AES-GCM) is sound; large-scale rotation is an R8/ADR-008 concern.

## 4. Process lessons

1. **One concern per commit** (explicit Reza feedback, 2026-06-05) — multiple concern-scoped commits per PR, one goal per PR; never a single fat commit. Adopted from the gateway slices onward (visible in `git log`).
2. **Flip status flags in the feature/closing PR**, not a follow-up — keeps `service_status.yaml` from lagging reality and cuts human asks.
3. **Docker smoke and unit smoke catch different failure classes** — multi-service work runs the docker smoke before opening the PR (§9.3).
4. **Trust `git log` over the GitHub UI** for merge state.
5. **Two-signature smoke** (`smoke.sh` key-free + real-substrate variant) is the right shape for the §22 smoke-vs-real gate.
6. **Reconcile every status surface before declaring done** — code can be real while a recorded status (a flag, a doc, the board) lags. This retrospective itself surfaced the lagged `claimed_done` flags and the stale services-reference status text (both corrected in this release-seam pass).

## 6. Forward plan

Honoring §8 (only the highest unfinished release is workable) and §23 (per-service, Reza-signed). R3.5 is closed; the recommended sequence next:

1. **Gateway error-contract slice (pull a thin slice of R6 forward — agreed with Reza).** The ORA-37 envelope contract is already pinned at `packages/errors/contract/` but has no Python emitter (`oraclous_errors` is an empty shell) and the gateway's GW-5 own-error body is non-conformant. Build the `oraclous_errors` emitter and make the gateway emit the canonical `{error: {code, message, requestId, retryable, details?}}` for its **own** errors **and normalize upstream 4xx/5xx** into it. This is the contract-correct seam (the envelope is defined as "what the gateway produces and the FE consumes"), gives the FE 100% uniform error coverage in **one** service, and corrects the GW-5 debt. Per-service native emission stays R6 (the FE never sees it — it only talks to the gateway).
2. **Fix the FE gates.** Stand up the FE lint / ruleset / gated-merge required checks so FE work is enforced by mechanism (parity with the BE stack). FE craft review stays CTO-owned (§8 frontend asymmetry).
3. **FE-first against the real gateway, scoped to current capabilities** (auth/orgs, credentials, knowledge-graph, retrieval, capability-registry **sync** execution). Agent-orchestration + streaming UIs wait for R4/R5.
4. **Plan R4 (harness-runtime-service)** — migration source map → ≤6 coarse slices → §22 8-gate.
5. **Plan R5 (execution-engine-service)** — async jobs + SSE streaming + active-jobs store; lift the Google Drive live connector with a secret-gated real smoke.
6. **R6 hardening — gateway as the contract surface** — per-service ORA-37 emission (if needed), sole-ingress (security-architect sign-off on the trusted-header threat), gateway OpenAPI as the canonical interface home.
7. **R7 / R8** — compiler harness + seed manifests; security hardening incl. credential key rotation (ADR-008).

**Guardrails carried forward:** concern-scoped commits; flip status flags in the feature PR; docker smoke for multi-service work; two-signature smoke; cross-org denial in every smoke; reconcile every status surface (board, `service_status.yaml`, KB) before declaring a goal achieved.
